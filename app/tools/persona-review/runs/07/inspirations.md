## Reference inspirations

### Core operator references

- https://github.blog/changelog/2026-01-22-improved-pull-request-files-changed-page-on-by-default/ — Better performance and navigation for large working sets; that is the bar for `/batches`, not card theater.
- https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/filtering-files-in-a-pull-request — File tree, filtering, and narrowed scope; make the explorer behave like a tool, not a brochure.
- https://docs.stripe.com/dashboard/basics — Practical ops chrome, task-first navigation, and a dashboard that assumes users came to do work.
- https://docs.stripe.com/dashboard/search — Search is not decorative; it is the shortest path to a known object.
- https://docs.stripe.com/workbench/overview — Error groups, endpoint context, and impact belong next to the object under inspection.
- https://grafana.com/docs/grafana/latest/visualizations/dashboards/build-dashboards/best-practices/ — Reduce cognitive load, keep drilldowns explicit, and stop making operators guess.
- https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/visualizations/table/ — Tables win when the job is comparison, filtering, and scanning real state.
- https://grafana.com/docs/grafana-cloud/introduction/dashboards/ — A dashboard is supposed to help operate a system; useful reminder because too many product teams forget it.
- https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/CloudWatch_Dashboards.html — Single operational view, cross-surface telemetry, and playbook bias over decoration.
- https://learning.postman.com/docs/sending-requests/response-data/responses — Response body, headers, code, time, size, and network details in one place; that’s honest UI.
- https://iterm2.com/features.html — Split panes and out-of-the-way search: keep context side by side and stop forcing serial navigation.

### Secondary pattern checks

- https://linear.app/docs/my-issues — Focused prioritization is useful, but only if it does not over-polish the underlying list.
- https://linear.app/docs/search — Keyboard-first lookup by ID/title is the right habit for power-user surfaces.

### Anti-references

- https://vercel.com/ — Good at selling capability, bad default posture for a proof explorer if copied literally.
- https://www.awwwards.com/websites/sites_of_the_day/ — A catalog of behaviors that optimize for novelty over repeat operational use.
- https://dribbble.com/search/website-shots — Shot culture produces fake-density UIs that collapse the minute real state shows up.
