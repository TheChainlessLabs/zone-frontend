# UI primitives — accessibility reference

Companion doc to the M2 design-system primitives. Every primitive ships
through `app/components/ui/__tests__/a11y.test.tsx`, which renders each
variant and asserts zero axe-core violations.

This file documents the **non-automatable** half of the audit:

- Keyboard interaction model per primitive (what `Tab`, `Enter`, `Arrow`
  etc. do).
- Focus-ring expectations.
- Known deferred items routed to M7 production hardening.

## Audit harness

- Tooling: `vitest-axe` wrapping `axe-core`.
- Run the subset: `pnpm test:a11y`.
- Run everything (the pre-commit gate): `pnpm test`.

Two axe rules are disabled in the harness because they cannot be
evaluated meaningfully at the primitive layer:

- `color-contrast` — jsdom does not compute CSS, so axe cannot read the
  cascaded `--foreground` / `--muted-foreground` token values. Contrast is
  audited end-to-end in a real browser as part of M7. See **Deferred** at
  the bottom.
- `region` — fires "page content is not contained by landmarks" against
  any node rendered outside `<main>`. Primitives are composed *into* page
  shells; landmark structure is the page author's responsibility, not the
  primitive's.

## Focus rings

Every interactive primitive uses the shadcn focus-visible pattern:

```
focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2
```

`ring-ring` resolves to `--ring`, which is `zinc-300` on dark themes and
`zinc-950` on light. Glass-variant primitives swap to
`focus-visible:ring-[var(--glass-highlight)]` so the focus ring reads
against the refraction substrate. Verified across:

| Primitive             | Focus ring           |
|-----------------------|----------------------|
| Button (all variants) | `ring-ring` ringed   |
| Input default         | `ring-1 ring-ring`   |
| Input glass           | `ring-1 glass-highlight` |
| Toggle                | `ring-1 ring-ring`   |
| Tabs.Trigger default  | `ring-2 ring-ring`   |
| Tabs.Trigger glass    | `ring-2 glass-highlight` |
| Tabs.Content          | `ring-2 ring-ring`   |
| DropdownMenu.Item     | inherits `focus:bg-accent` (Radix manages roving tabindex) |
| Dialog.Close          | `ring-2 ring-ring`   |
| Tooltip.Trigger       | inherits from the wrapped child (Button / Input) |
| Chip                  | `ring-1 ring-ring`   |
| Badge                 | non-interactive — no focus ring |
| Status                | non-interactive — no focus ring |

## Keyboard support

All Radix-backed primitives inherit Radix's keyboard contract. Listed
here so consumers don't have to dig.

### Button / Toggle / Chip

| Key            | Action                          |
|----------------|---------------------------------|
| `Tab` / `Shift+Tab` | move focus in/out          |
| `Enter`        | activate                        |
| `Space`        | activate (Toggle: also toggles) |

### Input

| Key            | Action                          |
|----------------|---------------------------------|
| `Tab` / `Shift+Tab` | move focus                 |
| All printable keys | type                        |

### Tabs

| Key                 | Action                                |
|---------------------|---------------------------------------|
| `Tab`               | move focus into / out of tablist      |
| `ArrowLeft` / `ArrowRight` | move between triggers (horizontal) |
| `ArrowUp` / `ArrowDown`    | move between triggers (vertical)   |
| `Home` / `End`      | first / last trigger                  |
| `Enter` / `Space`   | activate the focused trigger          |

Triggers carry `role="tab"` + `aria-selected`; the panel under each
carries `role="tabpanel"` + `aria-labelledby` (Radix-provided).

### Dialog

| Key            | Action                                  |
|----------------|-----------------------------------------|
| `Tab` / `Shift+Tab` | trap focus within dialog content   |
| `Esc`          | close dialog, return focus to trigger   |

`role="dialog"` + `aria-modal="true"` + `aria-labelledby` (DialogTitle)
+ `aria-describedby` (DialogDescription) wired by Radix.

### DropdownMenu

| Key                   | Action                              |
|-----------------------|-------------------------------------|
| `Enter` / `Space` / `ArrowDown` on trigger | open menu, focus first item |
| `ArrowUp` / `ArrowDown` | move between items                |
| `Home` / `End`        | first / last item                   |
| `ArrowRight` on submenu trigger | open submenu              |
| `ArrowLeft`           | close submenu                       |
| `Esc`                 | close menu, return focus to trigger |
| `Enter` / `Space`     | activate focused item               |

`role="menu"` on the content; items carry `role="menuitem"` (or
`menuitemcheckbox` / `menuitemradio` for the indicator variants).

### Tooltip

| Key            | Action                                  |
|----------------|-----------------------------------------|
| `Tab` to trigger | tooltip opens                         |
| `Esc`          | close                                   |

Trigger gets `aria-describedby` pointing at the tooltip content
(`role="tooltip"`), wired by Radix.

### Sheet (Drawer / vaul)

| Key            | Action                                  |
|----------------|-----------------------------------------|
| `Tab` / `Shift+Tab` | trap focus within drawer content   |
| `Esc`          | close drawer                            |

`role="dialog"` with `aria-labelledby` / `aria-describedby` wired by vaul.

### Form

`react-hook-form` + the shadcn-pattern wrappers wire up:

- `<FormLabel htmlFor>` → `<FormControl id>`
- `<FormControl aria-describedby>` → `FormDescription` id (and additionally
  `FormMessage` id when there's an error)
- `<FormControl aria-invalid>` → mirrors the field's error state
- `<FormMessage role="alert">` so screen readers announce validation
  errors as they appear

Required fields show a Linear-style accent dot via `<FormLabel required>`
— purely visual, marked `aria-hidden`. The label remains plain text for
screen readers, matching omega-docs voice rules.

### Status

`<Status>` renders inside a `Badge` and is non-interactive. When used as
a live status indicator (e.g. order timeline) the **consumer** should
wrap it with `role="status" aria-live="polite"` so screen readers
announce state transitions. The primitive does not impose `role="status"`
itself because not every Status placement is live (some are static
pills).

## Icon usage

Icons from `app/lib/icons.tsx` are rendered by Lucide as inline `<svg>`.
Default Lucide rendering does not include `aria-hidden`, so primitives
that compose icons must explicitly mark them:

- Decorative icon next to a text label → `aria-hidden`
- Standalone icon button (no visible text) → wrap the trigger with
  `aria-label="..."` on the button, then `aria-hidden` the icon

All current usages in this directory follow this convention. The Icon.X
in `Dialog.Close` is paired with a `<span class="sr-only">Close</span>`
for screen readers.

## Deferred to M7 production hardening

The harness here covers programmatic a11y. The following items require a
real browser or a human and are explicitly tracked for M7:

- **Color contrast.** axe `color-contrast` rule is disabled in this
  harness because jsdom can't compute CSS. Contrast must be verified in
  Lighthouse / axe-DevTools against the live tokens.
  - Specific watchlist: `text-muted-foreground` on `bg-muted`. If this
    fails WCAG AA at body size, the fix lives upstream in
    `omega-docs/03-brand/assets/tokens.json`, not in this repo. File a
    follow-up issue against omega-docs (Item Type: Decision) before
    patching tokens locally.
- **Manual screen-reader pass.** VoiceOver (macOS Safari) + NVDA (Win
  Firefox) walk-through of the primary flows. axe catches markup; only a
  human catches "the announcement order makes no sense" or "the focus
  jumps somewhere weird after submit".
- **Visible-focus subjective check.** axe verifies the ring exists; it
  does not measure perceived contrast of the ring against complex
  backgrounds (e.g. glass over MidpointTape). M7 visual-regression review
  covers this.
- **Reduced-motion compliance.** `Animate` already ships a
  reduced-motion path per variant, but the cross-primitive integration
  (motion + a11y interplay) is audited in M5 + M7.
